# Responsive and interaction audit — September 12, 2026

The Index is restored to a continuous image wall: zero horizontal padding,
zero gaps, and square corners. Its existing image order, aspect ratios and
2/3/4/5-column breakpoints remain intact. Enlarged lightbox images retain their
previous rounded treatment.

## Issues corrected

- High-density phones could jump from a small thumbnail to a 1600px original.
  Added 768px-wide gallery variants and corrected every source-set width to
  match the actual file. The gallery's source sizes now match its column widths.
- A failed full-size gallery request left an empty lightbox. The viewer now
  reuses the displayed responsive photo, or reports a failed image while its
  navigation and Close controls remain usable.
- Fresh `#nm-services` and `#work` links did not receive the post-hydration
  positioning correction used by About and Contact. All four public anchors
  now resolve after the layout mounts, unless the visitor has already interacted.
- Cloud Run's short-landscape layout excluded 568×320 phones, placing Exit
  above the scrollable area. Its CSS and logical stage now use matching
  orientation rules, with safe alignment for an unusually short viewport.
- Rotating the Index before its footer texture loaded threw a null-points
  error. Drawing now waits for readiness. Offscreen/hidden footer animation
  stays paused, and changes to reduced motion take effect immediately.
- Keyboard users opening the location popup could tab into the gallery
  instead of reaching its Maps link. Keyboard activation now focuses the link;
  Escape restores focus to the trigger.
- Opening the mobile menu while the location card was open left the card
  covering the menu. Outside-click dismissal now runs in the capture phase,
  including when the menu's own click handler stops propagation.
- Proposal screens now load the same responsive header rules as the public
  pages, including larger mobile hit areas.

## Coverage

The homepage and Index were checked in Playwright WebKit and Chromium at each
of these CSS viewport sizes:

```
320×568   360×800   375×667   390×844   414×896   430×932
568×320   667×375   844×390   600×960   768×1024  820×1180
900×1200  912×1368  1024×768  1366×1024 768×700   1280×720
1440×900  1600×900  1920×1080 2560×1440 3440×1440
```

1024×768 was checked separately with touch and fine-pointer input: 24 cases
per page and engine, or 96 primary page checks. These covered overflow, header
collisions, menus, services, touch previews, footer bounds and gallery controls.

Additional checks included:

- All 44 daily location labels across 11 sizes in both engines.
- All eight website previews, momentum scrolling, and pointer departure.
- Actual Home/Index clicks, browser Back/Forward scroll restoration, and
  direct public section links.
- Twelve complete down/up zoom cycles per engine, including portrait/landscape
  rotation. DOM and canvas counts remained stable; header controls did not
  duplicate. Chromium used 4× CPU throttling for these cycles.
- Reduced motion, Save-Data and rejected autoplay: photos remained available.
- Delayed video responses and first-frame playback on phone, tablet and desktop;
  no frame changed the collage's height.
- Gallery error recovery, keyboard paging, focus restoration and rotation.
- Compact Cloud Run layouts, Start/Pause/Resume/Exit, and rotation.
- Proposal access screens at seven sizes using synthetic empty data; no real
  proposal was opened or submitted.
- 503 decoded gallery variants for 170 photos, with verified source widths;
  all local references checked by the static validator.
- All eight linked public websites returned HTTP 200. Live missing-page and
  legacy proposal redirects reached their intended destinations.
- The 96 primary layout checks were repeated on the published release. All
  170 gallery photos and all six service images loaded without failed HTTP
  responses on high-density phone and desktop contexts. Gallery navigation
  also wrapped correctly from the last image to the first and back.

In the cold Chromium test at 390×844 and 3× DPR, with 150ms network latency,
200KB/s download throughput and 4× CPU throttling, recorded initial Index
resource transfers fell from approximately 7.80MB to 3.82MB. This is a
comparison under that test setup, not a universal page-load measurement.

## Repeatable checks

`docs/maintenance.md` lists the unit, browser and static validation commands.
`tests/responsive.browser.cjs` covers the new interaction regressions.
`tools/build-index-images.py --check` additionally validates image variants
when Pillow is available.

Desktop WebKit exercises Safari's engine, but it is not physical iPhone
hardware. These checks do not certify a frame rate on every phone or rule out
device-specific GPU, memory, browser-toolbar or thermal behavior.
