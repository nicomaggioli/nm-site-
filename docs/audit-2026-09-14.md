# Website optimization audit — September 14, 2026

Scope: the homepage, Work Index and About page, plus shared navigation, media, error routing, and Cloud Run. Three parallel audits used Ultra reasoning. The existing design, service order, resume content, edge-to-edge Index gallery, and animation behavior were preserved.

## Implemented

- Unique, descriptive titles and descriptions; one canonical URL per public page; complete Open Graph and Twitter cards. Homepage metadata agrees before and after React hydration.
- Linked WebSite and Person structured data, a ProfilePage for About, a CollectionPage for Index, and six Service entries using the actual service descriptions. No invented ratings, affiliations, or portrait claims.
- Image sitemap: three public canonical URLs and 254 image entries, including full-size gallery assets and the homepage's service images. Entries can repeat across pages that display the same image.
- Readable homepage with JavaScript disabled: introduction, six work images, six services, eight website links, and contact/navigation. Normal visitors retain the animated page and do not load the fallback stylesheet.
- A useful HTTP 404 page instead of redirecting missing public URLs home. Existing private proposal forwarding remains intact; private pages retain noindex and their crawl exclusion.
- Labeled navigation landmarks on Index and About, plus a keyboard skip link on Index. Navbar geometry and About gutters are unchanged.
- Disabled unsupported Next RSC prefetch on the logo, removed unused template data, matched the mask preload's CORS mode, and reused smaller responsive variants for two homepage photos. The intro cache waits for responsive source selection, avoiding a Chrome race that fetched full-size copies too.

## Measured loading changes

| Item | Before | After |
| --- | --- | --- |
| Unwanted homepage RSC prefetches | 4 | 0 |
| Hero mask downloads | 2 | 1 |
| Two center photos at 390px, 3× DPR | 395,960 bytes | 125,978 bytes |
| Local cold-load requests | 139 | 134 |
| Local cold-load transfer, audited snapshot | 4.61 MB | 3.71 MB |

The live baseline measured 105,036 compressed bytes spent on the four unnecessary prefetches. Responsive photos avoid 269,982 image bytes; deduplicating the mask avoids another 27,528 bytes. The local 19.6% reduction includes uncompressed HTML/JS and must not be represented as the production compression result. The final SEO fallback includes additional script-disabled content that does not load as imagery in the normal page.

Unthrottled desktop phone emulation measured a 16.7ms p95 intro frame interval and low offscreen work. These are laboratory checks, not a guarantee of performance on a physical iPhone. Existing animations already pause when offscreen or hidden; no further animation rewrite was justified by the audit.

## Verification

- All 44 unit tests pass, including the new responsive-source race and 404/private routing regressions.
- Static validation checks 675 local asset references, HTML/Flight consistency, and metadata/structured-data/sitemap integrity.
- Chromium and WebKit checks cover widths from 320 to 2560px, portrait/landscape, resume links, navigation history, keyboard focus, independent touch service expansion, live-site previews, gallery loading failures and recovery, and reduced motion.
- Responsive media A/B checks preserve collage, tile, track and document geometry at four intro positions. Delayed-video checks cover phone, tablet and desktop so posters stay visible during loading.
- Search metadata is checked after hydration on all public pages. Script-disabled checks verify the six images, six services, eight links, and About navigation at five widths.
- Cloud Run checks include unlocks, HUD, pause/resume, restart, touch targets, simultaneous controls, and rotation.
- The live crawl found no persistent broken public assets or external project links. HTTP and www redirect to the HTTPS apex. HTML aliases are consolidated with canonical tags.

## Search visibility limits

The changes improve technical crawlability and page information; rankings and inclusion are not guaranteed. Authenticated Search Console coverage, queries, and real-user Core Web Vitals were not available in this audit. The existing Search Console verification file remains intact. Sitemap submission and later coverage/performance review can be done in the site's existing Search Console property.
